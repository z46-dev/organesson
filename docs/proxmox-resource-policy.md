# Proxmox resource policy

- Platform administrators set optional global CPU, memory, storage, and SDN VNet limits; `0` means unlimited, including per-deployment SDN VNet limits.
- At least one Proxmox resource pool and storage must be selected before the policy can be saved.
- Organesson network labels map to existing Proxmox Linux bridges or SDN VNets, or declare an Organesson-created VNet. Existing targets come from current inventory, excluding VNets in Organesson's generated-name namespace. Created VNets use the administrator-selected VXLAN VNet source; Organesson creates and owns only its marked VNet and optional subnet, never the source zone. It selects a free VNI within that zone for each created VNet. Created VNets may declare managed IPv4 subnets with a gateway and optional DHCP. Address pools remain separate; their prefixes must fit inside a declared subnet when used with a created VNet.
- The selected VNet source zone is an existing Proxmox VXLAN zone shared across nodes. Configure its underlay and peers in Proxmox first. Selecting/importing it does not make the zone Organesson-managed: validation only reads it, and Organesson network destroy never deletes or edits it.
- SDN VNet limits are optional caps; zero leaves the count unlimited. The VNet's cross-node L2 behavior comes from its VXLAN source; egress and routing are separate concerns and are not created by Organesson's isolated L2 network.
- DHCP for a managed subnet requires a Proxmox SDN zone with DHCP integration and the required service on every node where guests may run. Organesson does not install host packages or modify the selected VXLAN source zone. Verify prerequisites before enabling DHCP.
- “Validate and save” reads current PVE pools, storage, bridges, VNets, and SDN zones, and saves only when every selected resource and the VNet source are visible in that inventory. It does not verify future write permissions or change Proxmox.
- PVE inventory cannot prove that an IP range on a bridge is reserved for Organesson or excluded from external DHCP. Admins must keep the declared allocation subnet out of all other address managers.
- Saving the policy does not reserve capacity. Address reservations occur when an OpenTofu `organesson_address_pool_request` is applied and are released when that resource is destroyed.
- The policy is stored in SQLite. Proxmox API credentials remain in the backend configuration.
